# 游戏编程模式

游戏编程模式是专为游戏开发而设计的一系列编程方法和架构模式。它们旨在解决游戏开发过程中遇到的特定问题，提高开发效率、代码可维护性和游戏性能。游戏编程模式通常结合了软件工程中通用的设计模式（如GOF设计模式），并针对游戏开发的特点进行了优化和扩展。

## 行为型模式

### 子类沙盒模式（Subclass Sandbox Pattern）

子类沙盒模式通过在基类中定义一个抽象的沙盒方法和一些预定义的操作集合，来允许子类根据这些操作定义自己的行为。这些操作通常被设置为受保护的状态，以确保它们仅供子类使用。

子类沙盒模式与模版方法模式是十分接近的，但是适用于需要子类通过组合预定义操作来实现行为的场景，强调子类的灵活性和扩展性。而模版方法模式适用于需要定义算法结构和步骤的场景，强调算法结构的一致性和规范性。

```cpp
#include <iostream>
#include <string>
#include <vector>

// 假设的音频系统
class AudioSystem {
public:
    static AudioSystem& Instance() {
        static AudioSystem instance;
        return instance;
    }

    void Play(const std::string& soundID) {
        std::cout << "Playing sound: " << soundID << std::endl;
    }
};

// 假设的粒子系统
class ParticleSystem {
public:
    static ParticleSystem& Instance() {
        static ParticleSystem instance;
        return instance;
    }

    void Spawn(const std::string& type, const std::vector<float>& position) {
        std::cout << "Spawning particles of type: " << type << " at position: ";
        for (float coord : position) {
            std::cout << coord << " ";
        }
        std::cout << std::endl;
    }
};

// 假设的英雄控制器
class HeroController {
public:
    static HeroController& Instance() {
        static HeroController instance;
        return instance;
    }

    std::vector<float> GetPosition() const {
        return {0.0f, 0.0f, 0.0f}; // 假设英雄在原点
    }
};

// 基类
class Superpower {
protected:
    virtual void Activate() = 0;

    void PlaySound(const std::string& soundID) {
        AudioSystem::Instance().Play(soundID);
    }

    void SpawnParticles(const std::string& type, const std::vector<float>& position) {
        ParticleSystem::Instance().Spawn(type, position);
    }

    std::vector<float> GetHeroPosition() {
        return HeroController::Instance().GetPosition();
    }

public:
    virtual void Update(float deltaTime) {
        if (CanActivate()) {
            Activate();
        }
    }

    virtual bool CanActivate() {
        return true;
    }
};
// 子类
class LightningBolt : public Superpower {
protected:
    void Activate() override {
        PlaySound("LIGHTNING_STRIKE");
        SpawnParticles("ELECTRICITY", GetHeroPosition());
        ApplyDamageToTargets();
    }

private:
    void ApplyDamageToTargets() {
        std::cout << "Applying damage to targets" << std::endl;
    }
};
```

### 类型对象模式（Type Object Pattern）

类型对象模式的核心思想是将对象的类型信息（如属性和行为）封装到一个独立的对象中，而不是直接嵌入到对象本身。这样，对象的行为可以通过引用类型对象来动态改变，而不需要修改对象本身的代码。

```cpp
// 类型对象
class Breed
{
  public:
    Monster * newMonster()
    {
      return new Monster(*this);
    }
    Breed(Breed* parent, int health , const char* attack): health_(health), attack_(attack)
    {
      // 继承parent数据
      if(parent != NULL)
      {
        parent_ = parent;
        if(health == 0) health_ = parent->getHealth();
        if(attack == NULL) attack_ = parent->getAttack();
      }
    }
  
    int getHealth() { return health_; }
    const char* getAttack( return attack_; )

  private:  
    int health_;
    const char* attack_；
    Breed * parent_;
};
// Breed 的实例
class Monster
{
  friend class Breed;

  public:
    const char* getAttack() { return breed.getAttack(); }

  private:
    Monster(Breed & breed)： health_(breed.getHealth()), breed_(breed) {}

    int health_;
    Breed& breed_;
};
  
```

## 解耦型模式

### 组件模式（Component Pattern）

组件模式的核心思想是将游戏对象的行为和属性分解为多个独立的组件，每个组件负责一个特定的功能。游戏对象通过组合这些组件来实现复杂的行为。这种模式通常包括以下几个主要部分：

* 组件接口（Component Interface）：定义了组件的基本接口。
* 具体组件（Concrete Component）：实现了组件接口，提供具体的功能。
* 游戏对象（Game Object）：包含多个组件，通过组合这些组件来实现复杂的行为。

```cpp
#include <iostream>
#include <vector>
#include <memory>
#include <string>

// 定义组件接口
class Component {
public:
    virtual void update(float deltaTime) = 0;
    virtual ~Component() = default;
};
// 移动组件
class MovementComponent : public Component {
public:
    void update(float deltaTime) override {
        std::cout << "Updating movement" << std::endl;
    }
};

// 渲染组件
class RenderComponent : public Component {
public:
    void update(float deltaTime) override {
        std::cout << "Rendering object" << std::endl;
    }
};

// 碰撞检测组件
class CollisionComponent : public Component {
public:
    void update(float deltaTime) override {
        std::cout << "Checking for collisions" << std::endl;
    }
};
class GameObject {
public:
    void update(float deltaTime) {
        for (auto& component : components) {
            component->update(deltaTime);
        }
    }

    void addComponent(std::shared_ptr<Component> component) {
        components.push_back(component);
    }

private:
    std::vector<std::shared_ptr<Component>> components;
};
int main() {
    // 创建游戏对象
    GameObject gameObject;

    // 添加组件
    gameObject.addComponent(std::make_shared<MovementComponent>());
    gameObject.addComponent(std::make_shared<RenderComponent>());
    gameObject.addComponent(std::make_shared<CollisionComponent>());

    // 更新游戏对象
    gameObject.update(0.016f); // 假设 deltaTime 为 0.016 秒

    return 0;
}

```

### 事件队列模式（Event Queue Pattern）

事件队列模式的核心思想是将事件存储在一个队列中，并在适当的时间（通常是游戏的更新循环中）处理这些事件。这种模式通常包括以下几个主要部分：

* 事件（Event）：表示一个具体的事件，如用户输入、游戏逻辑事件等。
* 事件队列（Event Queue）：存储事件的队列。
* 事件处理器（Event Handler）：负责处理事件的逻辑。
* 事件分发器（Event Dispatcher）：负责将事件分发给相应的处理器。

```cpp
 #include <iostream>
#include <queue>
#include <functional>
#include <memory>
#include <unordered_map>
#include <string>

// 定义事件基类
class Event {
public:
    virtual ~Event() = default;
};
// 用户输入事件
class InputEvent : public Event {
public:
    std::string input;
    InputEvent(const std::string& input) : input(input) {}

    std::string getType() const override {
        return "InputEvent";
    }
};
// 游戏逻辑事件
class GameEvent : public Event {
public:
    std::string message;
    GameEvent(const std::string& message) : message(message) {}

    std::string getType() const override {
        return "GameEvent";
    }
};
// 定义事件处理器
using EventHandler = std::function<void(const Event&)>;
class EventDispatcher {
public:
    void registerHandler(const std::string& eventType, EventHandler handler) {
        handlers[eventType] = handler;
    }

    void dispatch(const Event& event) {
        auto it = handlers.find(event.getType());
        if (it != handlers.end()) {
            it->second(event);
        }
    }

private:
    std::unordered_map<std::string, EventHandler> handlers;
};

// 事件队列
class EventQueue {
public:
    void enqueue(const Event& event) {
        events.push(event);
    }

    bool dequeue(Event& event) {
        if (!events.empty()) {
            event = events.front();
            events.pop();
            return true;
        }
        return false;
    }

private:
    std::queue<Event> events;
};
int main() {
    // 创建事件队列和分发器
    EventQueue eventQueue;
    EventDispatcher eventDispatcher;

    // 注册事件处理器
    eventDispatcher.registerHandler("InputEvent", [](const Event& event) {
        const InputEvent& inputEvent = static_cast<const InputEvent&>(event);
        std::cout << "Handling input: " << inputEvent.input << std::endl;
    });

    eventDispatcher.registerHandler("GameEvent", [](const Event& event) {
        const GameEvent& gameEvent = static_cast<const GameEvent&>(event);
        std::cout << "Handling game event: " << gameEvent.message << std::endl;
    });

    // 模拟事件产生
    eventQueue.enqueue(InputEvent("Jump"));
    eventQueue.enqueue(GameEvent("Level Completed"));
    eventQueue.enqueue(InputEvent("Shoot"));

    // 游戏主循环
    while (true) {
        Event event;
        if (eventQueue.dequeue(event)) {
            eventDispatcher.dispatch(event);
        } else {
            break; // 退出循环
        }
    }

    return 0;
}
```

### 服务定位器模式（Service Locator Pattern）

服务定位器模式是一种设计模式，用于帮助应用程序查找和获取所需的服务对象。它提供了一种间接的方式来访问服务，将服务的具体创建和查找过程封装在一个单独的定位器对象中，使得客户端代码不需要直接了解服务对象的创建细节和位置，从而降低了代码之间的耦合度。

服务定位器模式通常包含以下几个角色：

* 服务接口（Service Interface）：定义了服务的通用接口，客户端通过这些接口来使用服务。
* 具体服务（Concrete Service）：实现服务接口，包含具体的业务逻辑。
* 服务定位器（Service Locator）：负责查找、缓存和返回服务实例。
* 客户端（Client）：通过服务定位器获取服务并调用其功能，无需关心服务的创建或查找细节。
* 服务注册表（Service Registry）：存储服务实例或服务查找逻辑的容器。

```cpp
// 服务接口
class Audio
{
  public:
    virtual ~Audio() {}
    virtual void playSound(int soundID) = 0;
    virtual void stopSound(int soundID) = 0;
    virtual void stopAllSounds() = 0;
};
// 具体服务
class ConsoleAudio : public Audio
{
  public:
    virtual void playSound(int soundID) {}
    virtual void stopSound(int soundID) {}
    virtual void stopAllSounds() {}
};
// 空服务
class NullAudio : public Audio
{
  public:
    virtual void playSound(int soundID) {}
    virtual void stopSound(int soundID) {}
    virtual void stopAllSounds() {}
};
// 日志装饰器
class LoggedAudio : public Audio
{
  public:
    LoggedAudio(Audio &wrapped): wrapped_(wrapped) {}
    virtual void playSound(int soundID) 
    { 
      log("Play Sound");
      wrapped_.playSound(soundID);
    }
    virtual void stopSound(int soundID) 
    {
      log("Stop Sound");
      wrapped_.stopSound(soundID);
    }
    virtual void stopAllSounds() 
    {
      log("Stop All Sounds");
      wrapped_.stopAllSounds();
    }
   private:
    void log(const char* message) { }
    Audio & wrapped_;
};
// 定位器
class Locator
{
  public:
    static void initialize() { service_ = &nullService_; }
    static Audio& getAudio { return *service_; }
    static void provide(Audio* service) 
    { 
      if(service = NULL) service_ = &nullService_;
      service_ = service; 
    }
  private:
    static Audio * service_;
    static NullAudio * nullService_;
};
```

## 优化型模式

### 数据局部性模式（Data Locality Pattern）

数据局部性模式是一种优化技术，旨在通过合理组织数据，提高缓存利用率，从而提升程序的性能。在现代计算机系统中，缓存（如CPU缓存）的访问速度远快于主内存。因此，通过优化数据的存储和访问方式，使其更符合缓存的工作原理，可以显著减少缓存未命中（cache miss）的次数，从而提高程序的运行效率。

#### 连续数组

```cpp
AICompenet * aiComponents = new AIComponent[MAX_ENTITIES];
PhysicsCompenet * physicsComponents = new PhysicsCompenet[MAX_ENTITIES];
RenderCompenet * renderComponents = new RenderCompenet[MAX_ENTITIES];
// 游戏主循环
while(true)
{
  for(int i = 0; i < MAX_ENTITIES; ++i)
  {
    aiComponents[i].update();
  }
  for(int i = 0; i < MAX_ENTITIES; ++i)
  {
    physicsComponents[i].update();
  }
  for(int i = 0; i < MAX_ENTITIES; ++i)
  {
    renderComponents[i].update();
  }
}
```

#### 包装数据

数组利用率排序。

```cpp
class Particle
{
  public:
    void update() {}
};
class ParticleSystem
{
  public:
    ParticleSystem() : numParticles_(0) {}
    // 实际更新时跟踪numActive_，总是将激活的粒子排在数组前面，从而提高命中率。
    void update()
    {
      for(int i = 0; i < numActive_; ++i)
      {
        particles[i].update();
      }
    }
    // 激活粒子
    void activatePrticle(int index)
    {
      assert(index >= numActive_);

      Particle temp - particles_[numActive_];
      particles_[numActive_] = particles_[index];
      particles_[index] = temp;
      numActive_++;
    }
    // 反激活粒子
    void deactivatePrticle(int index)
    {
      assert(index < numActive_);
  
      numActive_--;
      Particle temp - particles_[numActive_];
      particles_[numActive_] = particles_[index];
      particles_[index] = temp;
  

    }
  private:
    static const int MAX_PARTICLES = 100000;
    int numParticles_;
    int numActive_;
    Particle particles[MAX_PARTICLES];
};
```

### 脏标记模式（Dirty Flag Pattern）

脏数据标记模式是一种优化技术，用于避免不必要的计算或数据同步。其核心思想是通过一个标志位（dirty flag）来标记数据是否发生了变化。如果数据没有变化，则直接使用缓存的计算结果，从而避免重复计算

```cpp
#include <iostream>
#include <vector>

// 假设的Transform类
class Transform {
public:
    static Transform origin() {
        return Transform();
    }

    Transform combine(const Transform& other) const {
        // 假设的组合逻辑
        return Transform();
    }
};

// 场景图节点
class GraphNode {
public:
    GraphNode(Mesh* mesh)
        : local_(Transform::origin()), world_(local), dirty_(true) {}

    void setTransform(Transform local) {
        local_ = local;
        dirty_ = true;
    }

    const Transform& getWorldTransform() {
        if (dirty_) {
            // 重新计算世界坐标
            world_ = local_.combine(parentWorld_);
            dirty_ = false;
        }
        return world_;
    }

    void render(const Transform& parentWorld, bool dirty) {
        dirty |= dirty_;
        if(dirty)
        {
          world_ = local_.combine(parentWorld);
          dirty_ = false;
        }  
        if(mesh_) rednerMesh(mesh_ , world_);
        for(int i = 0; i < numChildren_; i++)
          children_[i]->render(world_, dirty);
    }

private:
    Transform local_;
    Transform world_;
    GraphNode * children_[MAX_CHILDREN];
    int numChildren_;
    bool dirty_;
};


```

### 对象池模式（Object Pool Pattern）

对象池模式是一种设计模式，用于管理和复用一组初始化好的对象，避免频繁创建和销毁对象带来的性能开销。对象池预先创建并维护一个对象池，当需要使用对象时，从池中获取一个空闲对象；使用完毕后，将对象归还到池中，而不是销毁它。这样可以显著减少对象创建和销毁的开销，提高程序的性能。

核心组件：

* 对象池（Object Pool）：负责创建、管理和复用对象。
* 客户端（Client）：从对象池中获取对象，使用完毕后归还对象。
* 可复用对象（Reusable Object）：可以被对象池管理和复用的对象。

```cpp
#include <iostream>
#include <queue>
#include <mutex>
#include <memory>

// 定义可复用对象
class Reusable {
public:
    void use() {
        std::cout << "Object is being used." << std::endl;
    }

    void reset() {
        std::cout << "Object is being reset." << std::endl;
    }
};
// 对象池
class ObjectPool {
public:
    ObjectPool(size_t poolSize) {
        for (size_t i = 0; i < poolSize; ++i) {
            pool.push(std::make_shared<Reusable>());
        }
    }

    std::shared_ptr<Reusable> acquire() {
        std::lock_guard<std::mutex> lock(mutex_);
        if (pool.empty()) {
            return std::make_shared<Reusable>(); // 如果池为空，创建新对象
        }
        std::shared_ptr<Reusable> obj = pool.front();
        pool.pop();
        return obj;
    }

    void release(std::shared_ptr<Reusable> obj) {
        std::lock_guard<std::mutex> lock(mutex_);
        obj->reset();
        pool.push(obj);
    }

private:
    std::queue<std::shared_ptr<Reusable>> pool;
    std::mutex mutex_;
};
// 客户端
int main() {
    ObjectPool pool(5);

    // 获取对象并使用
    std::shared_ptr<Reusable> obj1 = pool.acquire();
    obj1->use();

    // 归还对象
    pool.release(obj1);

    // 再次获取对象并使用
    std::shared_ptr<Reusable> obj2 = pool.acquire();
    obj2->use();

    return 0;
}

```
